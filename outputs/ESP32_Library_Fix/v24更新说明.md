# v24 播放连续性排查版

本版本需要 STM32、ESP32 两端一起更新，接线和 Arduino 配置不变。v23 触摸校准保持兼容，正常情况下无需重新校准。保留 v20.9 和 v23 全部源码以供回退。

## 打开正确工程

- STM32：`STM32_Playback_Fix/Project/Player_v24.uvprojx`，Keil 编译下载。也可使用该工程 `Objects/BH-F103.hex`，但不要整片擦除校准区域。
- ESP32：`ESP32_Playback_Fix/ESP32_Playback_Fix.ino`，Arduino 上传。开发板 ESP32S3 Dev Module，Flash 16MB、OPI PSRAM、Huge APP 3MB，选择实际 COM 端口。
- 关闭旧 Arduino 窗口后打开新目录；新启动文字为 `Player touch fixes v24.0`，并有 `STM32 v24 ready; calibration complete`。

## 这次调整

1. MP3 的定位跳过量改为开始解码时计算一次，逐帧跳过；正常播放不再对每个采样进行 64 位时间除法。保留原有单声道混合、32kHz 输出、音量算法和 SPI 传输握手。
2. 新增轻量音频状态查询 AQ，只返回已播放采样数和缓冲量，不触发屏幕绘制。定期进度刷新间隔改为 1.2 秒；未暂停播放且排队少于 4096 采样（约128ms）时，暂缓进度和歌词绘制，优先供音频。
3. STM32 先确认进度/歌词指令，再进行绘制；ESP32 播放时这两种界面指令的等待上限缩短为40ms，避免原来最长1.8秒等待拖住音频。用户主动操作仍可强制更新。
4. 结束等待改用轻量队列查询，不再每10ms重绘进度。结束日志新增 `Audio UI: skipped=... poll-failed=... max-wait=... ms`。
5. 歌词失败保留具体 HTTP/TLS 数字或空响应/格式错误原因，不再全被“歌词服务请求失败”覆盖。保留 HTTPS 证书验证、HTTP/1.1 和已有关键词回退。不会输出歌词正文、访问密钥、账号令牌。

## 请按这个顺序验证

1. 两端更新后重新上电，确认启动版本与两端就绪提示。
2. 先播放本地 `test.mp3`，再播放一首大 MP3，注意速度、停顿；然后测试网络播放。
3. 播放中进入播放页，观察进度、歌词；供数紧张时刷新会变慢，这是本版主动取舍。
4. 如果仍有卡顿，请保留一次停止后的 `SD_UNDERRUN`、`Audio UI` 以及前面的传输统计。仅凭文件大小不能判断卡顿原因。
5. 如果歌词失败，请提供 `LRC /search failed...` 或 `LRC /download failed...` 附近几行。上一张启动截图没有歌词请求结果，尚不能确认实际失败原因。

## 验证与限制

- STM32 完整重编译：0错误、0警告。HEX 起始0x08000000、末地址小于0x0807F800，保留校准区域。
- ESP32 语法与完整编译均通过：Flash 46%、静态RAM 23%，详见构建验证记录。
- 新旧真实解码函数对同一测试MP3生成643072字节正常PCM，指纹均为8257b851c4c56d06，输出一致。
- 使用本版真实 MP3 函数运行本机解码测试：短定位输出与完整解码对应片段一致；8秒近似定位读取48528/120528字节，通过既有误差范围检查。
- 待用户实机验证：流畅度、歌词请求结果。当前属于有针对性的性能调整与诊断版，不能宣称歌词网络故障已解决。
- 原有简易重采样不是高保真滤波；本次没有更换音频转换算法，以免引入新变量。
