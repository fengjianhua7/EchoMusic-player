# ESP32 独立音乐接口实验版

## 范围和验证状态

ESP32直接访问酷狗网关，不运行Node.js服务，不依赖电脑中转音乐。
STM32固件和已验证的SPI/PA4接线保持不变。
实现标准版参数签名、持久化设备MID、搜索、用户验证、歌曲授权、链接解析、HTTPS MP3播放。
电脑侧匿名直连搜索已返回HTTP200、status1、error_code0，确认data.lists字段存在。
尚未在Arduino编译或ESP32硬件上验证本项目；歌曲授权和实际平台歌曲播放尚未验证。
这不是整个EchoMusic桌面软件移植。登录交互、扫码/短信、设备注册、验证码、歌单和完整错误恢复尚未实现。
无会话是否允许授权取决于平台响应；拒绝时停止，不绕过登录或付费限制。

## 操作

1. Arduino 文件->打开 ESP32_DirectMusic.ino。不要只从聊天预览旧文件。
2. config.h 已从上一版复制Wi-Fi配置，检查是否正确；无需改接线。
3. ESP32S3 Dev Module，选择正确COM端口，保持之前能上传的设置。
4. 上传，串口监视器115200。程序会联网并等待最多20秒网络校时。
5. 串口监视器右侧行结束设置选择“新行”或“NL和CR”。
6. 输入 s 歌曲名 并回车，例如 s 小星星。s后面有空格。
7. 出现1到5的搜索结果后，输入对应数字并回车，尝试授权和播放。
8. 输入 i 并回车，查看IP、时间同步及可用堆内存。
9. p仍可播放旧局域网测试MP3（该测试才依赖电脑文件服务）。

## 会话与错误

MUSIC_USER_ID默认0，MUSIC_TOKEN默认空，先测试匿名搜索。
若要求登录，不要把token、cookie或密码发到聊天。现阶段只支持在config.h本地填写已有会话；不支持在板上登录获取会话。
API错误会打印接口路径、HTTP状态、业务错误码和msg，不打印完整签名URL或token。
验证码要求会停止流程；此版本不实现验证码交互或自动绕过。
Clock not synchronized：校时失败，先检查网络，复位重试。
HTTP负数：网络/TLS失败；发错误行，勿分享config.h。
HTTP200但授权失败：接口访问成功但平台拒绝，需要进一步核对会话和响应。
没有结果：可能字段改变，需进一步适配；不要据此认为没有这首歌。

## 当前限制

仍仅支持MP3；平台返回AAC、OGG、FLAC或加密格式将无法正常播放。
音频要求明确Content-Length，不支持chunked。接口JSON由HTTPClient处理。
单声道32kHz，基础采样率转换无抗混叠滤波，网络/解码与SPI串行可能断音。
播放时串口命令不响应，没有停止/切歌控制；传输故障可能需要复位两块板。
TLS根证书来自本环境certifi的Mozilla CA集合，校验服务器证书及主机名，没有关闭证书验证。
HTTPS响应跨协议重定向仍需实测；不保证所有CDN链路可用。
