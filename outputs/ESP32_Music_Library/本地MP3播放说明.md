# v20：板载TF卡内MP3播放

## 新增返回线

断电后新增：指南者 B14（PB14 / SPI2 MISO）-> ESP32 GPIO13。
保留此前所有SPI、UART、GND及PA4音频接线，不要互接5V/3V3。
新固件必须两端同时更新，不能只刷一边。

## 下载

Keil：STM32_MP3_Card_Player/Project/BH-F103.uvprojx。
Arduino：ESP32_MP3_Card_Player/ESP32_MP3_Card_Player.ino。
设置 ESP32S3 Dev Module、16MB Flash、Huge APP、OPI PSRAM、原COM端口。
config.h复制自v19，账号会话仍使用原Preferences保存。

## 测试顺序

1. 在TF卡根目录放一首普通、无加密MP3，第一首建议小于2MB，文件名改成TEST.MP3。
2. FAT16/FAT32格式保持不变，断电插卡；保留TEST.WAV便于回归测试。
3. 两端下载后，手机打开ESP32局域网控制页，点击内存卡“读取列表”。
4. 应同时看到WAV和MP3；先试TEST.WAV，再点TEST.MP3的本地播放。
5. MP3会先载入ESP32缓存，手机显示载入进度，再开始播放；不是点击后立即发声。
6. 如串口出现 Local MP3 return block CRC/ACK failed，先核对新增B14->GPIO13返回线，再发日志。
7. 验证暂停/恢复、停止、音量与下一首。

## 实现和限制

STM32通过SDIO读文件，经SPI MISO返回512字节块，每块CRC32校验。
ESP32将整首MP3缓存至PSRAM，解码后把32kHz单声道PCM经原MOSI链路返回STM32 DAC。
最大文件6MB，并且要求可用PSRAM比文件大小多至少256KB；不足时明确拒绝，不部分播放。
首次载入需要等待，时间取决于卡速度和双板块协议开销。尚未实现MP3流式预取。
支持普通MP3，不支持加密音乐文件、AAC、OGG、FLAC或将其他格式改扩展名为MP3。
根目录最多列20个WAV/MP3；文件系统为8.3短文件名模式，中文长文件名可能显示别名。
本版本在线下载仍保存WAV；暂不支持将在线歌曲原始MP3直接保存到卡。
不要在读卡/下载中拔卡，停止操作并断电后取卡。
手机控制仍需局域网，未加入离线路由器的文件触摸菜单。
原v19下载临时文件、CRC确认后保存WAV、不覆盖现有文件等行为保留。

## 验证状态

STM32 Keil完整编译：0错误、0警告，Code30640、RO-data245864、RW-data244、ZI-data16076字节。
ESP32完整源码通过本机工具链语法检查；完整链接、运行内存及真实SPI返回链路尚未验证。
手机页面脚本语法检查通过；缓存载入、CRC、MP3播放需要实物测试。
v20.1：新增GBK长文件名转UTF-8显示；本地打开改用STM32文件列表索引，不再将网页显示名称作为文件路径回传。须两端更新后重新读取列表。
v20.2：改为SPI分块读取并直接解码，取消整首PSRAM缓存及6MB上限。STM32继续使用v20.1固件；手机页显示文件大小。ESP32语法及网页脚本检查通过，实际流式吞吐和断音仍需上板验证。前文整首缓存等待及6MB限制在此版不再适用。
v20.3：两端UART同步改为115200，SPI同步改为4MHz，STM32音频环形缓冲8192采样（256ms），MP3常规补充改为每次最多1024字节。必须两端同时更新。电脑串口监视器仍115200。播放结束输出SD_UNDERRUN统计（缺少的采样数）；暂停也可能产生欠载，因此先不暂停验证连续播放。吞吐和电气可靠性需上板验证，CRC/ACK错误时检查短接线与共地。
