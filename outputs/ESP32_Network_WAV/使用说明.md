# 第三阶段：Wi-Fi 与网络 WAV

保持已验证的 STM32 固件、SPI 接线及 PA4 音频电路不变。
Arduino IDE 打开 ESP32_Network_WAV.ino。同目录 config.h 会成为另一个标签页。
仅使用 ESP32 支持包自带的 WiFi、HTTPClient、SPI，无额外库。

1. 在 config.h 的 WIFI_SSID、WIFI_PASSWORD 双引号中填写自己的 2.4GHz Wi-Fi 名称和密码。
2. WAV_URL 先留空，上传，打开115200串口监视器，按ESP32 RST。
3. 出现 Wi-Fi OK, IP: ... 即联网成功。发送 i 查看状态。
4. 后续将 WAV_URL 填为可访问的 HTTP 音频文件直链，重新上传；发送小写 p 开始播放。
5. 要求 PCM、16位、单声道、32000Hz WAV。不是 MP3，也不是网页/歌单地址。
6. 当前只接受直接返回200的普通HTTP响应；不支持HTTPS、跳转、分块传输、压缩响应。
7. 结束或网络中断后，STM32播放完缓冲并静音。重新发送p可重试。

无需电脑提供音频服务：文件可以由路由器/NAS或可访问的HTTP服务器提供。
电脑仅用于编辑/烧录/观察日志。暂时没有合适的WAV直链时，先验证联网，不代表网络音频已验证。
这不是最终EchoMusic接入程序；下一阶段需要MP3解码、TLS/接口适配及更充分的网络缓冲。
继承上一版SPI固定长度实验协议，无校验与帧重同步。ACK超时后程序停止发送，需复位两端。
网络读取与SPI发送目前串行进行，抖动较大时可能断音，后续改为独立下载任务与音频队列。

验证状态：已静态检查长度边界、RIFF子块及填零处理；当前环境未找到ESP32编译工具，尚未编译或上板。
