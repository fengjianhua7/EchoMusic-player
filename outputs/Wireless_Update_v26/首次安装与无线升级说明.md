# v26 双端无线升级与下载修复

本版为两端升级基础版：首次仍需有线安装；之后在同一 Wi-Fi 下，用手机或电脑浏览器上传固件。两块开发板只需正常供电，原有板间 UART/SPI 接线保留，不需要增加 BOOT0/复位控制线。

重要：引导程序、升级页面与数据完整性检查已编译/本机模拟验证，尚未在你的开发板上执行升级或断电恢复测试。首次安装后，先用同版本升级包做一次无线上传和重启验证，再依赖无线升级。

## 一、首次安装：按顺序操作一次

### 1. STM32 安装引导程序

1. 保留 FireDAP，打开 `STM32_OTA_Bootloader/Project/Bootloader_v26.uvprojx`。
2. Keil 使用 CMSIS-DAP / SW / under Reset；Flash Download 选择 **Erase Sectors**，不要选整片擦除。
3. 编译并下载这个工程。它写入引导程序、识别字和初始更新标记，不会写触摸校准区。
4. 下载后尚未安装新应用时没有正常播放器界面属于预期，立即继续下一步。

### 2. STM32 安装移位后的播放器应用

1. 打开 `STM32_OTA_Player/Project/Player_v26.uvprojx`，保持 **Erase Sectors**。
2. 编译并下载。这个应用的起始地址为 **0x08008000**，与旧版不同；不要使用 v25 工程代替。
3. 重新上电，引导程序会启动应用；原有末尾2KB触摸校准数据保持兼容。若曾整片擦除，则需要重新校准。

引导程序代码区0x08000000..0x08007000，识别字0x08007000，更新标记页0x08007800，应用0x08008000..0x0807F800，校准0x0807F800..0x08080000。代码/固件包构建检查这些边界。

### 3. ESP32 首次安装双程序分区

1. Arduino 打开 `ESP32_OTA_Player/ESP32_OTA_Player.ino`。
2. 开发板 `ESP32S3 Dev Module`，Flash `16MB`，PSRAM `OPI PSRAM`。
3. **Partition Scheme 选择 Custom**，保留本工程根目录的 `partitions.csv`，不要删除或替换它。Erase All Flash 保持 Disabled。
4. 连接数据线并选择实际COM端口，上传一次。普通上传会同时安装分区表及应用。
5. 新启动文字为 `Player wireless update v26.0`，STM32就绪协议为26。等待连上原来的Wi-Fi。

ESP32 使用两个6MB程序槽；OTA写备用槽，校验通过后切换启动。旧版Huge APP单槽不能直接改成这个布局，首次必须有线安装。NVS地址保持原来位置，但首次如果选择整片擦除，账号等本机设置会丢失。

## 二、之后无线升级：不用电脑数据线

1. 手机或电脑连接播放器所在 Wi-Fi。
2. 打开 `http://stm32music.local/upgrade`；若设备不支持.local解析，用实际IP，例如 `http://192.168.1.209/upgrade`。IP以路由器设备列表或首次安装串口显示为准。
3. 点击 **进入升级模式**。音乐会停止；下载/写入繁忙时请先等完成。
4. 查看STM32屏幕上的8位升级码，在网页输入。码3分钟有效，错误尝试最多5次；重新进入升级模式生成新码。升级码不从网页状态接口公开。
5. 选择升级设备和文件，点击 **上传并升级**，观察进度及状态。

| 设备 | 选择文件 | 不要选择 |
|---|---|---|
| ESP32 | `ESP32_v26.ota.bin`（应用程序bin） | merged、bootloader、partitions、STM32包 |
| STM32 | `STM32_v26.stmfw` | 普通bin、hex、旧版0x08000000应用 |

ESP32校验后自动重启。STM32先把完整包写到TF卡，校验并提交后重启，由引导程序检查并写入应用；写入时保持TF卡插入和电源稳定。升级后恢复播放器页面，并重新读取TF目录，重建STM32本地文件索引。首次测试可上传同版本；相同STM32应用会跳过重复擦写，但仍验证上传、校验、重启流程。

后续固件必须保留OTA功能及相同分区/应用起址；页面不能替换引导程序或修改ESP32分区表。引导程序本身若需变更，仍要有线更新。本版提供局域网入口，没有配置公网穿透。

## 三、STM32 更新恢复机制

- 升级包包含机型、应用起址、长度、向量检查与CRC；文件全量验证后才擦写应用，保留引导程序和校准区。
- 上传期间保留 `FWUPD.TMP` 未完成标记；未提交的包不会启动写入。
- 引导程序擦写前设置独立Flash标记，写完并核对Flash内容后清除。若中途断电，已提交的有效TF包保留，重新上电可重新尝试；不会仅凭尚存的中断向量跳入半写入应用。
- 如果TF卡损坏或丢失，无法承诺纯无线恢复。可用读卡器把有效 `.stmfw` 复制为根目录 `STMUPD.BIN`，确认复制完成后移除残留 `FWUPD.TMP`，插回上电；或保留FireDAP恢复。不要在未复制完整有效包时移除标记。
- CRC校验保证完整性，不等同于发行者数字签名；本版用屏幕升级码控制上传。新固件自身逻辑错误也不保证自动回滚。

## 四、音乐下载与显示修复

针对你的 `SD_ERR:RENAME`：旧版传输结束后改名失败，不能算下载完成；原旧TMP文件保留，未自动删除或判断为有效歌曲。

新下载流程不再改名：先写未完成标记和数据文件，长度/CRC、刷卡、关文件全部成功后，移除未完成标记才加入曲库。未完成项目从播放器曲库隐藏；电脑直接看卡时可能看到数据文件与标记，不能据此当作完整歌曲。

SD写入改为8KB集中写入，减少512字节逐次写卡开销；实机提速幅度未测，不作速度承诺。

屏幕新增：
- 百分比、进度条、已接收/总KB；
- 平均KB/s和预计剩余秒数；
- 独立“正在校验并保存”“下载完成”状态；
- 取消下载/完成后返回列表；
- 保存失败显示具体FatFs错误及保留的文件信息，不会停留在“正在下载”。

下载页重新清理整页区域，提示页重新绘制顶栏/底栏，减少残留。预览图数字是模拟数据，不是测速结果。

## 五、长时间暂停恢复

你的日志已显示歌词66行获取成功，播放失败对应后续网络读取超时。

- STM32在暂停时冻结音频队列读取与播放计时，恢复后继续；停止/切歌清除暂停状态。
- 网络歌曲暂停10秒及以上后恢复：重新获取地址，从暂停位置重新连接，避免继续使用可能已经失效的旧连接。位置沿用近似定位方案，依赖服务器支持Range。
- 本地MP3恢复使用原读卡队列，不进行网络重连。
- 网络/读卡超时显示具体原因，不再一律归为“文件格式或传输接线”。

## 六、构建与打包

- STM32未来应用继续使用0x08008000起址、协议26和最后2KB校准预留。
- 编译应用后，运行本目录 `make_stm32_package.py`（Python3）；默认读取本版应用及引导HEX，输出 `.stmfw`、应用bin及首次安装合并HEX，检查地址和向量并生成manifest。
- 初次安装推荐以上两个Keil工程顺序下载；合并HEX供支持HEX下载的工具使用，不直接当成OTA包。
- Arduino“项目 → 导出已编译二进制文件”产生应用bin。网页只上传应用bin，带merged字样的整片镜像不能用于OTA。
- 本目录将附带本次编译的 `ESP32_v26.ota.bin`，首次安装仍推荐Arduino上传完整工程。

详细验证结果见 `构建与验证记录.txt`。旧v25及正常基线v20.9完整源码未覆盖。
